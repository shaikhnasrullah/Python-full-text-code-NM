1. Introduction

FRALEN CRM is a web-based Customer Relationship Management (CRM) system specifically designed for optical shops and eyewear retail businesses. The system provides a complete digital solution for managing customers, sales orders, prescriptions, and business analytics — accessible through any modern browser without installation.

The name FRALEN represents the brand identity of the CRM platform, developed as a college final project to demonstrate full-stack web development skills using modern cloud technologies. The system is deployed on GitHub Pages with Firebase as the backend infrastructure, making it accessible from any device with an internet connection at zero server cost.

1.1 Project Overview

Optical shops in Pakistan and India typically rely on manual, paper-based systems for customer management and order tracking. FRALEN CRM addresses this gap by providing a cloud-based solution that handles:

  • Customer records and full prescription history management
  • Sales order creation with automated GST and discount calculations
  • Real-time business analytics dashboard
  • Secure multi-user authentication with route protection
  • Collapsible sidebar navigation for efficient workflow

2. Problem Statement

Optical shops are a critical part of the healthcare retail industry, serving customers with corrective eyewear prescriptions. Despite their importance, most small and medium optical retailers in Pakistan and India still rely heavily on manual, paper-based systems for customer management, order tracking, and prescription records.

2.1 Identified Problems

2.1.1 Manual Record Keeping

Optical shops maintain customer prescriptions and order details in physical registers or notebooks. This leads to data loss, illegible handwriting errors, and inability to retrieve historical records quickly. When a returning customer needs their old prescription, staff must manually search through hundreds of paper records.

2.1.2 No Centralized Customer Database

Customer information — including contact details, prescription history, and purchase records — is scattered across different systems. Some data exists in notebooks, some in Excel sheets, and some stored only in the shopkeeper's memory. There is no single source of truth, leading to inconsistencies and poor customer service.

2.1.3 Manual Billing and Calculation Errors

Order calculations involving GST, discounts, advance payments, and pending balances are done manually. This is prone to arithmetic errors, leading to customer disputes and financial discrepancies. There is no automated record of what was charged, making auditing impossible.

2.1.4 No Business Insights or Analytics

Without a digital system, optical shop owners have no visibility into key business metrics such as daily sales, pending collections, monthly revenue trends, or customer growth. Business decisions are made based on intuition rather than data.

2.1.5 Expensive Existing Solutions

Professional optical shop management software exists (e.g., OpticalCRM, VisionBase), but these are subscription-based with monthly fees that are unaffordable for small shops. There is a clear need for an accessible, free, or low-cost alternative that small retailers can use without technical expertise.

2.2 Proposed Solution

FRALEN CRM addresses all the above problems by providing a free, browser-based system requiring no installation. Using Firebase's free tier (Spark Plan), the system provides cloud data storage, real-time synchronization, and secure authentication — making enterprise-level features accessible to small optical retailers at zero infrastructure cost.

3.4 Dashboard Analytics

3.4.1 Total Customers

Fetched using getDocs() on the customers Firestore collection. The total document count gives total customers, while createdAt is compared to the current month to count new additions this month.

3.4.2 Today's Sales

Calculated by iterating all orders and summing totals.payable for documents where createdAt matches today's date (day, month, year comparison). This provides real-time daily revenue visibility.

3.4.3 Pending Orders and Balance Due

Orders with totals.pending > 0 are counted as pending. The sum of all pending amounts gives the total Balance Due — a critical metric for cash flow management in optical shops where customers often pay in installments.

3.4.4 Recent Orders Table

All orders are sorted by createdAt in descending order, and the top 5 are displayed in the dashboard table showing customer name, item count, payable amount, date, and payment status (Paid/Pending badge).

4. Methodology

FRALEN CRM was developed using an iterative, feature-driven development methodology. The project was built incrementally — starting with core UI structure, then adding business features, and finally integrating Firebase backend connectivity.

4.1 Development Phases

Phase 1 — Planning and Design

Requirements were gathered based on real optical shop workflows. Manual wireframes outlined the dashboard layout, navigation structure, and key page flows. The UI design language was established — navy (#1B2A6B) and accent blue (#4F6BF0) color palette, Inter for body text, and Montserrat for brand typography. Key design decision: minimize JavaScript frameworks to ensure GitHub Pages compatibility.

Phase 2 — Frontend Development

All pages were built as standalone HTML files with embedded CSS and JavaScript. This deliberate choice ensures compatibility with GitHub Pages static hosting without any build tools, compilers, or npm workflows on the server:

  • index.html — Splash screen (2-second animation) + Firebase-connected login form
  • dashboard.html — Stats cards, Chart.js charts, quick actions, recent orders table
  • customers.html — Customer list with search/filter, add modal, Firestore CRUD
  • create-order.html — 10-row product table with auto-calculations, prescription modal

Phase 3 — Firebase Integration

Firebase was integrated using CDN ES Module imports from gstatic.com. This avoids npm dependencies that would require a build step, making the system directly deployable as static HTML. Three Firebase services were integrated:

  • Firebase Auth — Email/Password signIn, onAuthStateChanged for route protection
  • Firebase Firestore — addDoc() for saves, getDocs() for reads, deleteDoc() for deletes
  • Route Guards — Every protected page checks auth state and redirects if unauthenticated

Phase 4 — Business Feature Implementation

  • Auto-calculating order totals with real-time oninput event listeners
  • Lens prescription modal with RE/LE fields — auto-triggers on Lens type selection
  • Collapsible sidebar with CSS width transition (220px ↔ 64px) and icon tooltips on collapse
  • Sales submenu dropdown with smooth max-height CSS animation
  • Dashboard live data fetching — getDocs() queries populate stats and recent orders table

4.4 Data Flow

  • User visits site → Splash animation plays → Firebase auth state checked via onAuthStateChanged()
  • If authenticated → Dashboard renders → Firestore queried for real-time stats and orders
  • If not authenticated → Any protected page redirects to index.html login
  • User logs in → signInWithEmailAndPassword() → onAuthStateChanged fires → redirect to dashboard.html
  • User creates order → Form data collected → addDoc(db, "orders", orderObject) → toast + redirect
  • User adds customer → addDoc(db, "customers", custObject) → table re-renders with Firestore data
  • User logs out → signOut(auth) → redirect to index.html

4.5 Security Implementation

  • Firebase Authentication ensures only registered users can access the system
  • All protected pages include onAuthStateChanged() listener — unauthenticated access redirects to login
  • Firebase config is the standard public config (API Key is not a secret in Firebase — it identifies the project, not authenticates)
  • Firebase Security Rules in Firestore can restrict read/write access per authenticated user
  • No backend server means no server-side vulnerabilities; all security is handled by Firebase's infrastructure

5.3 Testing Results

5.3.1 Authentication Flow

The login system was tested with correct credentials, incorrect passwords, and non-existent emails. Firebase returns specific error codes which are mapped to user-friendly messages. The splash screen, form validation, and dashboard redirect all function correctly. Direct URL access to protected pages correctly redirects to login.

5.3.2 Order Processing Accuracy

Orders with multiple product types were tested. Price auto-fill from product selection, GST calculation (tested with 5%, 12%, 18%), discount deduction, round-off, and pending amount computation were all verified to be mathematically accurate. The lens prescription modal correctly triggers only when at least one row has "Lens" as product type.

5.3.3 Firestore Data Persistence

Customer and order data was verified to persist correctly in Firebase Firestore via the Firebase Console. Data appears correctly in the customers collection and orders collection with all fields populated. Dashboard statistics update dynamically on each page load to reflect current Firestore data without manual refresh.

5.4 Limitations

  • Product catalog is currently hardcoded in JavaScript — not yet managed from Firestore
  • Sales History page (sales-history.html) is linked but not yet developed
  • Dashboard charts (bar chart, donut chart) display placeholder data, not live Firestore aggregates
  • No invoice/receipt print or PDF generation feature yet
  • No role-based access control (all authenticated users have full access)

5.5 Future Scope

  • Products and inventory module with full Firestore CRUD and stock alerts
  • Invoice/receipt generation with print and PDF export
  • WhatsApp integration for sending prescriptions and delivery notifications
  • Monthly and custom date range reporting with Chart.js Firestore integration
  • Barcode scanner integration for product lookup using device camera
  • Role-based access control (Admin, Staff, Viewer roles)
  • Multi-branch support with branch-level data separation
  • Customer birthday and follow-up reminder system

5.6 Conclusion

FRALEN CRM successfully demonstrates that a fully functional, cloud-connected business management system can be built using only frontend technologies (HTML, CSS, JavaScript) combined with Firebase's Backend-as-a-Service platform — with zero server cost and zero installation requirements.

The system directly addresses the core pain points of optical shop management: manual prescription record keeping, calculation errors in billing, data loss, and lack of business insights. By deploying on GitHub Pages with Firebase Firestore as the cloud database, FRALEN CRM achieves professional-grade functionality at no cost — making it accessible to small optical retailers in Pakistan and India who cannot afford expensive commercial alternatives.

This project demonstrates proficiency in modern web development technologies, cloud database integration, UX/UI design principles, business workflow analysis, and software deployment — core competencies for a software engineering professional and a strong foundation for further development into a production-ready SaaS product.
